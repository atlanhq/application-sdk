    Configuration Reference

    The Application SDK reads configuration from environment variables at startup. Variables are grouped below by subsystem. The canonical source of truth is application_sdk/constants.py (import-time constants) and application_sdk/main.py (AppConfig runtime values).

    Set variables in your shell environment or Docker ENV / Kubernetes ConfigMap / Secret resources. For local development, a .env file at the project root also works: see .env.example at the repo root for a ready-to-copy template.

    The .env file

    Only run_dev_combined() reads ./.env, as its first step, and a variable already set in the environment wins over the file. Importing application_sdk reads no file, so a production process never loads one.

    run_dev_combined() runs after the SDK is imported, and the settings in application_sdk/constants.py are read at import. So a .env value reaches the runtime settings (AppConfig: ports, Temporal connection, task queue) but not the import-time ones (log level, OpenTelemetry exporters, application name in log tags). To apply the file to those too, load it before Python starts:

    uv run --env-file .env python run_dev.py

    The log line Loaded <names> from ./.env after the SDK was imported lists the variables the file set late.

    How values are read

    Every variable follows the same rules:

    • Unset or empty means the default. An unset Helm value renders as "", so an empty value is treated as not configured. This holds for string variables too (names, paths, URLs): ATLAN_APPLICATION_NAME= means default, not an empty name. Surrounding whitespace is ignored.
    • A malformed value means the default, with a warning. OTEL_BATCH_SIZE=abc or an inf timeout does not stop the process. It logs a warning naming the variable and the value, and uses the default. Values read at import time (most of this page) warn on stderr, because logging is not set up yet. Values read later warn through the SDK logger.
    • Booleans: true, 1, yes and on enable. false, 0, no and off disable. Matching is case-insensitive and ignores surrounding whitespace. Any other word warns and keeps the default.
    • Choices (for example ATLAN_OOM_RESTART_CHECK, ATLAN_DEPLOYMENT_ARTIFACT_DUAL_WRITE): an unrecognised word warns and keeps the default.
    • Durations (the ATLAN_OBSTORE_*_TIMEOUT variables): one or more number-and-unit terms such as 30s, 90s, 1h 30m or 1.5h. Units are ns, us, ms, s, m, h, d, w, M (months) and y, plus their long forms. A bare number has no unit and is rejected (it warns and keeps the default), except 0, which is accepted as zero, as the object-store client accepts it.

    ATLAN_SQL_USE_SERVER_SIDE_CURSOR is the one exception: an explicitly empty value disables server-side cursors, as it always has.

    This page covers runtime variables only. Variables starting E2E_ configure the test harness under application_sdk/testing/. CI sets them, and a deployed app never reads them. See Runtime vs test-harness variables.

    Application

    Variable Default Description
    ATLAN_APP_MODULE (required) App class to load: module.path:ClassName (e.g. app.app:MyExtractor). Startup fails without it. Set in your Dockerfile as ENV ATLAN_APP_MODULE=… or pass via --app CLI flag.
    ATLAN_APP_MODE combined Run mode: worker, handler, or combined. Determines which subsystems start; override via --mode CLI flag. v2-compat fallback: APPLICATION_MODE (deprecated; case-insensitive; LOCAL/WORKER/SERVER map to combined/worker/handler, and the v3 names are accepted as-is. An unrecognised value logs a warning and runs combined).
    ATLAN_APPLICATION_NAME default Application name. Used in object-store paths, logging, and workflow identification. The default fallback applies to those identity uses only — task-queue derivation treats the variable as genuinely unset (see Task-queue naming). Set it as the bare name, with no atlan- prefix; the SDK adds the prefix.
    ATLAN_DEPLOYMENT_NAME local Deployment name. Distinguishes dev / staging / prod deployments of the same app. As with ATLAN_APPLICATION_NAME, the local fallback is an identity default and does not apply to task-queue derivation.
    ATLAN_TENANT_ID default Tenant identifier for multi-tenant deployments.
    ATLAN_DOMAIN_NAME atlan.com Tenant domain name.
    ATLAN_TEMPORARY_PATH ./local/tmp/ Path for intermediate files during processing.
    APPLICATION_SDK_ENABLE_CLEANUP_INTERCEPTOR true End-of-run cleanup. Read once at worker start and pinned on each run, which keeps the value it started with on any pod. When false, the default on_complete() skips cleanup_files() and cleanup_storage(), and a worker that releases a closed run's app state keeps the local files that run's tasks tracked. The run's app-state slot is still released and its cached clients closed.
    ATLAN_CLEANUP_BASE_PATHS (empty) Comma-separated object-store prefixes cleaned up by cleanup_files(). Defaults to the workflow-scoped run path when unset.
    ATLAN_CONTRACT_GENERATED_DIR app/generated Directory for generated contract JSON (configmaps, manifest). In Docker (WORKDIR=/app) this resolves to /app/app/generated.
    ATLAN_FRONTEND_ASSETS_PATH app/generated/frontend/static Path to static frontend assets served by the handler.

    Release metadata

    Two sources, baked first. build-and-publish-app.yaml writes app/atlan_build.json into the image (app_version, commit_sha, image, built_at); the SDK reads it at startup. Deployers (Local Marketplace into the Helm release, the SDR orchestrator into the container) may still stamp env vars. When both exist the file wins: it describes the image, the env var describes what a deployer thinks it deployed. Images built before this CI started baking the file have no file and fall back to the env vars, then empty. Exposed to consumers via the OTel target_info gauge (one row per pod). Leave empty for local development. See standards/release-flow.md#image-identity.

    Variable Default Description
    ATLAN_APPLICATION_VERSION (empty) Version of the app release as Global Marketplace stores it (release tag for semver apps, sha7 for CD apps). Used only when the baked file is absent or has no app_version.
    ATLAN_COMMIT_SHA (empty) Git commit the image was built from. Used only when the baked file is absent or has no commit_sha. Deployers do not normally stamp this.
    ATLAN_BUILD_INFO_PATH app/atlan_build.json Override the baked-identity lookup for non-template layouts whose Dockerfile does not copy app/. When unset, the SDK also tries <parent of ATLAN_CONTRACT_GENERATED_DIR>/atlan_build.json.
    ATLAN_BUILD_ID (empty) Immutable image tag, stamped as an image ENV by the e2e build action. Takes precedence over the baked file's build_id; both are read by application_sdk.app.build_identity.build_identity(). Not set on released images, which carry the value in the file instead.
    ATLAN_RELEASE_ID (empty) Release UUID from Global Marketplace. Injected by the deployer.
    ATLAN_RELEASE_CHANNEL (empty) Release channel (all, beta, staging, specific).
    ATLAN_SDK_VERSION (empty) SDK version used to build this app image.
    ATLAN_APP_TYPE (empty) App type from Global Marketplace (e.g. connector, system).
    ATLAN_PUBLISHED_AT (empty) Release publication timestamp (ISO 8601).
    ATLAN_APP_ID (empty) Global Marketplace's id for this app — the card's installation_id. One per app and stable across releases and tenants, unlike ATLAN_RELEASE_ID. Not yet stamped by any deployment, so every reader must tolerate an empty value and send nothing rather than a substitute.

    Preflight results store

    Where the injected preflight gate appends its verdict. The route is served by another repo — see standards/cross-repo-contracts.md before changing either value.

    Variable Default Description
    ATLAN_PREFLIGHT_RESULTS_ENDPOINT http://system-workflows.system-workflows-app.svc.cluster.local:8000/continuous-preflight/check-results The whole write URL, path included — never composed from parts. Override to point at a stub off-cluster.
    ATLAN_PREFLIGHT_RESULTS_TIMEOUT_SECONDS 30 Bound on that POST. Generous because the receiving app opens a Polaris catalog, may create the table and commits a Parquet file. Nothing waits on it.

    SQL clients

    Variable Default Description
    ATLAN_SQL_CLIENT_CONNECT_TIMEOUT_SECONDS 60 Bound on a SQL client's load(): building the connection string (including the STS AssumeRole for IAM-role auth) plus the first connect. Expiry raises SqlClientConnectTimeoutError. Also passed as connect_timeout to psycopg2, psycopg and MySQLdb, which have no connect timeout of their own, unless DB_CONFIG.connect_args or the URL already sets one. For IAM-role auth, the STS AssumeRole call's limits (5 s connect, 15 s read, 2 attempts) shrink to fit the time left, so a hung STS call frees its worker thread by the deadline too.

    Temporal / Workflow

    Variable Default Description
    ATLAN_TEMPORAL_HOST localhost:7233 Temporal server address (host:port). v2-compat fallback: if unset, the SDK constructs the address from ATLAN_WORKFLOW_HOST + ATLAN_WORKFLOW_PORT (deprecated; remove when all deployments set ATLAN_TEMPORAL_HOST).
    ATLAN_TEMPORAL_NAMESPACE default Temporal namespace. v2-compat fallback: ATLAN_WORKFLOW_NAMESPACE.
    ATLAN_TASK_QUEUE (derived) Temporal task queue name. Defaults to atlan-{ATLAN_APPLICATION_NAME}-{ATLAN_DEPLOYMENT_NAME} when both are set, or just the bare app name (no atlan- prefix) when only ATLAN_APPLICATION_NAME is set, or {ClassName}-queue (kebab-case) when neither is set. Setting this explicitly also changes the queue the served manifest advertises, so a worker on an overridden queue and the Automation Engine stay in step. The override is for local and CLI runs: do not pin it in a deployed app's deploy or pool env (contract/app.pkl or atlan.yaml) — the on-demand (-od) worker then polls the base queue and its retries hang (conformance rule K031). See Task-queue naming.
    APPLICATION_SDK_ENABLE_OUTPUT_INTERCEPTOR true Collect get_outputs() metrics and artifacts and merge them into the workflow result. Each activity carries its outputs back on its own result (metrics / artifacts on an Output, or a reserved _atlan_outputs key on a dict result, which the workflow strips from its own dict result), so they arrive whichever worker runs the activity. An activity returning anything else (e.g. None) cannot carry them: they are dropped with a warning. Set it on workflow and activity workers alike.
    ATLAN_TEMPORAL_PROMETHEUS_BIND_ADDRESS 127.0.0.1:9464 Bind address for the Temporal SDK Prometheus endpoint (~40 built-in metrics). Loopback-only by default — operators should not scrape this port directly; combined-mode FastAPI /metrics proxies it in-process. See Monitoring.
    APPLICATION_SDK_ENABLE_EVENT_INTERCEPTOR true Publish lifecycle events (workflow and activity start/end) through the event binding. Read once at worker start and pinned on each run the worker starts, so a run publishes (or not) according to the worker that started it.
    ATLAN_POOL_<POOL>_QUEUE (derived) Task queue for tasks declared with @task(pool="<pool>"). <POOL> is the pool name upper-cased with - replaced by _ (cold-tier reads ATLAN_POOL_COLD_TIER_QUEUE). Unset means <task queue>-<pool>, from ATLAN_TASK_QUEUE or the derived queue.
    ATLAN_WORKFLOW_MAX_TIMEOUT_HOURS (unset: no limit) Execution timeout, in hours, the handler sets on the workflows it starts. Unset, 0 or negative means no timeout (a negative value logs a warning).
    TEMPORAL_HOST localhost:7233 Read by load_execution_settings() into ExecutionSettings.host, with ATLAN_WORKFLOW_HOST + ATLAN_WORKFLOW_PORT as the fallback. The SDK's own worker and client do not use this field: they connect with ATLAN_TEMPORAL_HOST. Set that one.
    TEMPORAL_NAMESPACE default Read into ExecutionSettings.namespace. Not used by the SDK's worker or client, which read ATLAN_TEMPORAL_NAMESPACE.
    TEMPORAL_TASK_QUEUE application-sdk Read into ExecutionSettings.task_queue. Not used by the SDK's worker or client, which read ATLAN_TASK_QUEUE.

    Task-queue naming

    The queue name has to be agreed on by two things that never talk to each other: the worker, which polls it, and the served manifest, whose resolved task_queue the Automation Engine writes into the DAG and submits work to. When they disagree nothing fails loudly — AE submits to one queue, the worker polls another, and the run sits unclaimed until its 24h heartbeat backstop.

    There is now one derivation, application_sdk.common.task_queue.derive_task_queue, and the manifest route does not re-run it — it stamps the queue the handler was configured with, which is the same value the worker was started on. Two paths deriving the same answer is a convention; one path copying the other's answer is structural.

    The rule itself:

    ATLAN_APPLICATION_NAME ATLAN_DEPLOYMENT_NAME Queue
    dbt prod atlan-dbt-prod
    dbt (unset) dbt — bare, no prefix
    (unset) anything no queue name exists; the worker falls back to {ClassName}-queue for local dev, and the manifest stamps that same queue. With no app name available anywhere, the served manifest leaves the literal {app_name} token in place and logs at ERROR

    Two consequences worth internalising when writing or rewriting an AE DAG outside the toolkit:

    • Pass the bare app name. derive_task_queue adds the atlan- prefix. Prefixing a value that is already prefixed produces atlan-atlan-dbt-production, a queue nothing polls.
    • Never invent a name for the unset case. atlan-default-prod reads as a legitimate queue and reproduces the original silent hang; a literal {app_name} in the DAG is greppable and diagnosable in one step. That is why ATLAN_APPLICATION_NAME's default fallback is scoped to identity uses and excluded here.

    Do not pin ATLAN_TASK_QUEUE in a deployed app. The chart runs an on-demand variant of the worker with -od appended to ATLAN_DEPLOYMENT_NAME, so the derivation gives it its own queue, atlan-{app}-{deployment}-od. An explicit ATLAN_TASK_QUEUE in the contract's deploy or pool env (or in atlan.yaml) overrides the derivation for both variants, so the -od worker polls the base queue. When a worker pod is lost, the activity rerouter moves the retry to the -od queue, nothing polls it, and the run hangs until its workflow timeout. Conformance rule K031 flags the pin. Setting it for a local or CLI run (--task-queue) is fine.

    Nodes that dispatch to a different app's queue (atlan-publish-{deployment_name} and friends) are legitimately not this app's queue: their {deployment_name} token is filled and the value is otherwise left alone.

    Worker Versioning

    Used by the Temporal Worker Deployment controller (TWD). Leave empty unless your cluster uses versioned deployments.

    Variable Default Description
    ATLAN_APP_BUILD_ID (empty) Build ID for worker versioning. Fallback: TEMPORAL_BUILD_ID.
    ATLAN_APP_DEPLOYMENT_NAME (empty) Worker Deployment name (<namespace>/<twd-name>). Fallback: TEMPORAL_DEPLOYMENT_NAME.
    TEMPORAL_DEFAULT_VERSIONING_BEHAVIOR PINNED Versioning behavior for workflows that declare none, when the worker registers as a Worker Deployment version. PINNED or AUTO_UPGRADE (case-insensitive); any other value logs a warning and uses PINNED.

    Task timeouts and progress

    Process-wide defaults for @task timing, read once at startup. An explicit value on @task(...) always wins. See Tasks: process-wide timeout defaults.

    Variable Default Description
    ATLAN_START_TO_CLOSE_TIMEOUT_SECONDS 86400 (24 h) Default timeout_seconds: Temporal ends one activity attempt after this many seconds.
    ATLAN_HEARTBEAT_TIMEOUT_SECONDS 60 Default heartbeat_timeout_seconds: Temporal retries the activity when no heartbeat arrives within this window. The framework heartbeats every 10 s.
    ATLAN_SCHEDULE_TO_CLOSE_TIMEOUT_SECONDS (unset: unbounded) Default schedule_to_close_seconds: ceiling on a task's total time across every retry. 0 reads as unset; a negative value logs a warning and is ignored.
    ATLAN_PROGRESS_WATCHDOG warn Stall-watchdog mode: off, warn or enforce. off disables the watchdog and beats a per-task declaration. An unrecognised value logs a warning and uses warn.
    ATLAN_MAX_NO_PROGRESS_SECONDS 900 Default max_no_progress_seconds: how long an attempt may report no progress before the watchdog reports a gap. 0 or negative uses the default.
    ATLAN_RUN_LENGTH_SLA_SECONDS 86400 (24 h) How long a run may take before the run-length alert is raised. 0 disables it. See Tasks.
    ATLAN_SDR_<OP>_START_TO_CLOSE_SECONDS 300 Per-attempt timeout for one SDR handler activity. <OP> is AUTH (test_auth), PREFLIGHT (preflight_check) or METADATA (fetch_metadata).
    ATLAN_SDR_<OP>_SCHEDULE_TO_CLOSE_SECONDS 300 Total-time ceiling for the same SDR activity across retries. A value lower than the matching start-to-close timeout logs a warning, because Temporal rejects that pair.

    Worker Restart Supervisor

    Bounds the restart supervisor that rebuilds the worker after a fatal poll error (e.g. a transient auth failure) instead of exiting. Defaults are sensible; override only to tune restart behavior.

    Variable Default Description
    ATLAN_WORKER_MAX_CONSECUTIVE_RESTARTS 10 Consecutive worker-fatal failures tolerated before the supervisor gives up and re-raises, so a persistent misconfiguration still fails loud instead of hot-looping. The counter resets after a healthy run window.
    ATLAN_WORKER_RESTART_BACKOFF_CAP_SECONDS 30 Upper bound (seconds) for the full-jitter exponential backoff between worker restarts. The backoff is raced against shutdown so SIGTERM stays responsive.
    ATLAN_WORKER_HEALTHY_RUN_SECONDS 300 A worker that ran at least this long (seconds) before failing is treated as a fresh incident, resetting the consecutive-failure streak.
    ATLAN_WORKER_POLL_DIAGNOSTIC_INTERVAL_SECONDS 60 How often (seconds) to read Temporal core's live poller gauge and log a state transition, so a worker that is alive but claiming no work is visible in logs and in the /live / /ready probe details. Its readings also drive the two poll-loop /live checks below, so the time those take to trip scales with this interval. Set to 0 to disable (the zero-poller check then never trips, and the fatal check can never see a recovery).
    ATLAN_WORKER_ZERO_POLLER_READINGS_BEFORE_STALE 3 Consecutive definitive zero-poller readings before this worker stops emitting token_refresh health events. At the default 60s observer interval that is ~3 minutes of confirmed-parked polling. unknown / polling never accumulate toward this threshold.
    ATLAN_WORKER_LIVENESS_MAX_ZERO_POLLER_READINGS 5 Consecutive definitive zero-poller readings before the worker /live probe returns 503, so Kubernetes restarts a pod that is alive but polling nothing. About 5 minutes at the default observer interval. unknown / polling reset the count. Set to 0 to disable.
    ATLAN_WORKER_LIVENESS_FATAL_RECOVERY_SECONDS 600 Seconds a fatal poll error may go without a later polling reading before the worker /live probe returns 503. When the poller gauge cannot be read, no recovery is visible, so every fatal restarts the pod after this bound. Set to 0 to disable.
    ATLAN_WORKER_LIVENESS_MAX_IMPORT_WAIT_SECONDS 300 Seconds one thread may wait on the same module import lock before the worker /live probe returns 503. Temporal's deadlock interrupt (TMPRL1101) can land inside Python's import system and leave a thread waiting on an import forever; every later import of that module then hangs while the worker keeps polling, so activities fail by heartbeat timeout. A healthy import never waits this long. Set to 0 to disable.
    ATLAN_WORKER_FATAL_TEARDOWN_TIMEOUT_SECONDS graceful shutdown timeout + 60 Upper bound (seconds) on temporalio's own worker teardown after a fatal poll error. The supervisor regains control only when that teardown returns; if it has not returned within this bound the process exits with code 1 so the pod or container restart policy brings up a fresh worker. 0 or negative disables the bound.
    ATLAN_SHUTDOWN_GRACE_SECONDS unset The pod's terminationGracePeriodSeconds. Kubernetes' Downward API cannot expose that field, so the chart sets this env var from the same value. When set, the drain (TEMPORAL_GRACEFUL_SHUTDOWN_TIMEOUT), the post-drain deadline (ATLAN_POST_DRAIN_EXIT_TIMEOUT_SECONDS) and the Pushgateway shutdown bounds (ATLAN_PROMETHEUS_PUSHGATEWAY_HTTP_TIMEOUT_SECONDS, ATLAN_PROMETHEUS_PUSHGATEWAY_SHUTDOWN_DELETE_DELAY_SECONDS) default to values derived from it, and the event-loop stall bound (ATLAN_WORKER_LOOP_STALL_TIMEOUT_SECONDS) is capped so it still fires before SIGKILL. The drain comes first: in-flight activities are the one step that is not best-effort, and daprd stays up for the whole drain because the entrypoint stops it only after Python exits. The steps after the drain (post-drain deadline and daprd's stop) would ideally get min(120, grace/4) + min(30, grace/10). They never take that from a drain of up to TEMPORAL_GRACEFUL_SHUTDOWN_TIMEOUT (or its 3600 s default): they get what the grace leaves beyond that drain, but never less than 10 s, and the drain gets the rest after ATLAN_SHUTDOWN_DRAIN_DELAY_SECONDS. A 12 h grace keeps 120/10/35 s and drains for ~12 h. A 3660 s grace keeps the full 3600 s drain, and the Pushgateway hold shrinks into the 55 s left. A 30 s grace drains for 15 s. An explicit value for any single bound still wins. At startup the worker logs the effective budget, and logs a WARNING when explicit bounds add up to more than the grace. Unset, every bound keeps its fixed default. A grace too short to cover ATLAN_SHUTDOWN_DRAIN_DELAY_SECONDS plus a 1 s post-drain deadline also keeps the defaults, with a warning. The WARNING about explicit bounds counts the daprd headroom too.
    ATLAN_WORKER_LOOP_STALL_TIMEOUT_SECONDS derived Replaces the event-loop stall bound for a shutting-down worker. SIGTERM is handled on the event loop, so a loop stuck in a lock wait or an untimed blocking call never shuts down: Temporal's core keeps polling on its own threads and takes tasks the process cannot run until SIGKILL, and the kubelet no longer runs liveness probes on a terminating pod. The stall watchdog closes that gap and is armed only by the first SIGTERM or SIGINT; before shutdown a frozen loop is left to a liveness probe on the worker's /live, which runs on the same loop. It arms from a process-level signal handler, which the interpreter runs only when the main thread is back in Python bytecode. A loop already frozen in a lock wait (threading.Lock and the like) or in a blocking system call that Python retries after a signal (PEP 475: open, read, sleep, ...) is covered. A native call that keeps waiting inside C delays the arming until it returns, whether or not it released the GIL (a database driver's busy-wait, for example), and a native call that never returns (a driver or Rust/C mutex) never arms it, which leaves that freeze to SIGKILL. A freeze that starts after the signal is always covered. While the loop runs through the drain it keeps pushing the deadline back, and it is stopped when the drain ends and ATLAN_POST_DRAIN_EXIT_TIMEOUT_SECONDS takes over. If the loop does not run for the bound, the process writes every thread's stack to stderr and exits with code 1 (the timer runs the bound plus one re-arm interval, min(bound/4, 15 s), so the loop has been silent for at least the bound, unless the SIGKILL cap below cut it short). Unset, the bound is 15 s past the longest heartbeat_timeout_seconds among the registered tasks (at least the 60 s default), so a stall during the drain never ends work Temporal still counts as alive. Tasks without a heartbeat timeout do not count: once the loop stops they are indistinguishable from a freeze, and Temporal reclaims them only at their start-to-close timeout; startup logs a WARNING naming each app task without a heartbeat timeout whose start-to-close timeout is longer than the bound. With ATLAN_SHUTDOWN_GRACE_SECONDS declared the bound is also capped so the exit lands before SIGKILL with daprd's headroom left (a 30 s grace gives 22.4 s), and the drain's re-arms never push the exit later than that point after the signal, so a freeze that starts late in the drain still ends the process before SIGKILL. The derived drain timeout ends before that point, so the cap only ends a drain that overruns it (an activity still running after it was cancelled, for example); that exit has the same stack dump and code 1 even though the loop may still be running, so the loop first logs a WARNING ("Shutdown drain still running at the exit deadline") saying the dump that follows marks the deadline, not a stalled loop. The bound shows as loop_stall= in the startup Shutdown budget line, with a WARNING when longest heartbeat timeout < bound <= what still fires before SIGKILL does not hold because of an override or a task's own heartbeat timeout (the WARNING names the task). When only the SDK's default heartbeat timeout (ATLAN_HEARTBEAT_TIMEOUT_SECONDS) is longer than a short grace allows, the same fact is logged at INFO, since no task is at fault. Set it to 0 to turn the watchdog off, for example when debugging a worker locally, where a breakpoint during shutdown would otherwise end the process. Applies when the app is started through the SDK's entry point (python -m application_sdk.main), in worker and combined mode. Malformed, negative or non-finite values are ignored with a warning.
    ATLAN_POST_DRAIN_EXIT_TIMEOUT_SECONDS 120, or derived from ATLAN_SHUTDOWN_GRACE_SECONDS Upper bound (seconds) on shutdown after the worker has drained on a shutdown signal. It is armed as soon as the Temporal drain returns, so it also covers the worker's own cleanup: credential directories, sizing rows, and the Pushgateway final push, hold and DELETE. It also covers closing infrastructure, flushing telemetry and interpreter exit hooks. No activity is in flight by then; if these steps have not finished within the bound the process exits with code 3, so a stuck telemetry flush cannot hold the pod for its whole grace period. The container entrypoint passes code 3 through as the container's exit code. Applies when the app is started through the SDK's entry point (python -m application_sdk.main); awaiting run_worker_mode / run_combined_mode directly does not start it unless bound_post_drain_exit=True. 0 or negative disables the bound.
    DAPR_STOP_TIMEOUT_SECONDS 30 Read by the container entrypoint. How long to wait for daprd to exit once the Python app has exited before killing it. Once the app has exited, daprd has nothing left to do: inbound pub/sub and bindings have no app to deliver to, and the app has no outbound call in flight.
    ATLAN_TEMPORAL_CORE_METRICS_MAX_BYTES 1048576 Upper bound (bytes) on every read of Temporal core's loopback metrics endpoint: the poll-state diagnostic, the combined-mode /metrics proxy and the worker's Pushgateway TemporalCoreCollector.     The deployment object store is required

    Every app reads and writes artifacts, credential files and observability exports through the deployment object store, so worker, handler and combined startup build it unconditionally. When no Dapr component named DEPLOYMENT_OBJECT_STORE_NAME exists in DAPR_COMPONENTS_PATH, startup logs an ERROR and fails with DeploymentObjectStoreMissingError (a StorageBindingNotFoundError, so existing except StorageBindingNotFoundError: / except StorageConfigError: handlers still catch it; audience APP_OWNER). The component-diagnostics pass at startup also logs the missing object store at ERROR, never as "disabled by config (expected)".

    The usual cause is the app's contract: the atlan-app chart omits the component when atlan.yaml carries deploy.dapr.objectstore: false. Set it to true (dapr { objectstore = true } in contract/app.pkl), regenerate and redeploy. contract-toolkit defaults it to true, and conformance rule K029 flags a contract or atlan.yaml that sets it to false.

    The error does not depend on ATLAN_ENABLE_OBJECTSTORE: the chart sets that variable on the env-seeder init container, not the app container, so the app usually sees it unset. When it is visible and false, the error message says so.

    Which Dapr components a deployed app gets

    The Local Marketplace deployer turns the deploy.dapr block of atlan.yaml into the atlan-app chart's dapr.components.<name>.enabled values. It fills each component the block leaves out (or the whole block, when there is none) with its own default: true for objectstore and secretstore, false for the rest. A value the block states always wins, including false. The chart's own values have every component off, so these deployer defaults are what an app without a dapr block runs with.

    Once a contract has a deploy block, contract-toolkit renders every component whenever at least one resolves to true (or customComponents is non-empty), so the contract decides each one. When every component resolves to false (for example objectstore = false on an app without credentials), the toolkit emits no dapr block at all, and the deployer's defaults above apply instead. secretstore defaults to true for an app that resolves credentials (hasCredentialConfig or additionalCredentialConfigs, on the app or any entrypoint): the SDK resolves every credential through it, and without it each lookup fails with HTTP 500 from /v1.0/secrets/<store>/<guid>. Conformance rule K030 flags secretstore: false on such an app.

    ATLAN_DEPLOYMENT_ARTIFACT_DUAL_WRITE best_effort Controls dual-write behaviour when both stores are configured (SDR only). best_effort (default): artifact is written to the deployment (customer) store and the upstream (Atlan) store; a deployment-write failure logs a WARNING and the run continues. required: same dual-write, but a deployment-write failure causes the run to fail after the upstream write completes (a copy is guaranteed somewhere). disabled: upstream-only write (pre-BLDX-1464 behaviour).
    ATLAN_VALIDATE_ASSETS_ON_UPLOAD true Validate transformed assets against the pyatlan_v9 backbone before the SDR→Atlan upload handoff. Warn-only — invalid/orphaned assets are logged, never block the upload. Set to false to disable the check entirely.
    ATLAN_VALIDATE_ASSETS_TIMEOUT_SECONDS 600 Upper bound in seconds for one upload's asset-validation scan. The scan runs in an isolated child process (CNCT-85); past this bound the child is killed and the upload proceeds with a warning, so warn-only validation can neither stall nor crash a handoff.
    ATLAN_VALIDATE_ARTIFACTS true Deployment-level kill switch for artifact validation. When on, an outcome event is emitted for every artifact. false stops validation and its events. Whether a verdict blocks is ATLAN_ARTIFACT_VALIDATION_MODE.
    ATLAN_ARTIFACT_VALIDATION_MODE (the app's artifact_validation_mode, else soft) hard makes a failed artifact validation block; any other non-empty value is soft. Overrides the app class's declaration.
    ATLAN_FAULT_ISOLATION_IDLE_SECONDS 30 Seconds a fault-isolation process pool (run_fault_isolated / run_best_effort, which the asset-validation scans use) keeps its spawn children after its last call finishes. Past it the children exit and their memory returns to the pod; the next call spawns afresh. 0 shuts the pool down as soon as it goes idle. Read when a pool goes idle, so a change applies from the next idle period. A value that isn't a non-negative number is ignored, with one warning. See ADR-0017.
    SSL_CERT_DIR (empty) Directory of custom CA certificates (.pem, .crt, .cer, .ca-bundle). Used by the SDK's httpx clients when set.

    Outbound proxy

    Every SDK connection that can go through an egress proxy resolves it with one rule (application_sdk/_proxy.py): the BaseClient HTTP transport, the obstore object-store clients, the Temporal connection and the S3 bucket-region lookup.

    1. The proxy for a connection is its scheme's variable, then ALL_PROXY: HTTPS_PROXY for TLS connections (object stores, a TLS Temporal endpoint, https:// requests), HTTP_PROXY for plaintext ones. HTTP_PROXY is never used for a TLS connection.
    2. A host matching NO_PROXY connects directly: an exact host, a domain suffix (.example.com or example.com match subdomains), or * for every host. A port on the host is ignored. obstore receives the raw list as proxy_excludes and matches it per request itself.
    3. Only the process environment is read. The lowercase spelling (https_proxy) wins over the uppercase one. Operating-system proxy settings (macOS System Settings, the Windows registry) are ignored, so a laptop resolves the same way a pod does.
    Variable Default Description
    HTTPS_PROXY (empty) Proxy URL (http://[user[:password]@]host:port) for TLS connections.
    HTTP_PROXY (empty) Proxy URL for plaintext connections.
    ALL_PROXY (empty) Proxy URL for any connection whose scheme variable is unset.
    NO_PROXY (empty) Comma-separated hosts and domain suffixes that connect directly.

    Common Patterns

    Local development

    Most defaults work out of the box for local development with uv run poe start-deps (starts Dapr + Temporal). The key variables to override:

    ATLAN_APP_MODULE=app.app:MyExtractor
ATLAN_APPLICATION_NAME=my-extractor
ATLAN_LOG_LEVEL=DEBUG

    ATLAN_LOCAL_DEVELOPMENT (app-level, not read by the SDK)

    The SDK itself does not read ATLAN_LOCAL_DEVELOPMENT; it infers local development from the registered components. Many connector main.py files still read it, as a contract between the app and the SDK's CI: when it is true and DAPR_HTTP_PORT is unset, main.py calls app.run_dev, which boots an embedded daprd and an in-process Temporal. Otherwise it calls application_sdk.main.main(), which expects an external Dapr sidecar.

    The shared connector-integration-tests action sets ATLAN_LOCAL_DEVELOPMENT: "true" on its "Start app server" and test steps, and on SDK 3.13+ it starts no external daprd or Temporal. Removing the variable from the action leaves those apps with no sidecar, and they fail at startup with DaprNotDetectedError. .github/scripts/tests/test_connector_integration_local_dev_env.py pins it. Because apps still read it, it is not in _REMOVED_ENV_VARS, and setting it does not trigger the removed-variable warning.
