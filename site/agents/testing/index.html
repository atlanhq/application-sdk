    Testing

    • Test commands: docs/agents/dev-commands.md (Testing), the one place they are written down. Conventions: docs/standards/testing.md.
    • New code should target 85% coverage per docs/standards/review-checklist.md (the tooling threshold in pyproject.toml is 85% — CI fails below it). The same floor applies to each top-level application_sdk subpackage on its own, except those listed with a different floor in [tool.application-sdk.coverage.package-floors]; the coverage leg uploads coverage.xml and htmlcov/ as the sdk-unit-test-coverage artifact (14 days).
    • Current tests live in tests/unit/, which mirrors application_sdk/: application_sdk/a/b/c.py → tests/unit/a/b/test_c.py (so _runtime/ → tests/unit/_runtime/, execution/_temporal/interceptors/ → tests/unit/execution/_temporal/interceptors/). tests/unit/test_unit_tree_mirrors_package.py fails a test directory with no package counterpart; a deliberate exception goes in its _NOT_MIRRORED with what it tests instead.
    • Before writing a local double, look for a shared one. tests/unit/_doubles.py holds FakeClock (an injected monotonic clock with advance), StaticHandler (a Handler whose entry points succeed empty), SiblingProbe (fan-out first-failure), loaded_after_importing / loaded_after_running (fresh-interpreter import probes), record_connect_params (SQLAlchemy do_connect recorder) and the Temporal interceptor inputs; MockSecretStore records get_optional calls (get_get_optional_calls()), so a store that only records or answers from a dict is a MockSecretStore. Directory fixtures live in the nearest conftest.py: store in tests/unit/storage/ (memory) and tests/integration/ (local), mock_next in tests/unit/execution/_temporal/interceptors/, and the emulator guards require_minio / require_azurite / require_testbench in tests/integration/storage/ (opt in with pytestmark = pytest.mark.usefixtures("require_minio")). A double used by one module stays in it; move it to _doubles.py when a second module needs it.
    • Keep a test module under 1,500 lines. When one grows past that, split it by the area it covers and move shared handlers and factories into a support module beside it — tests/unit/handler/test_service_*.py share _service_support.py.
    • A unit test that takes ≥10s on its own (a throughput comparison, a 100k-key scale probe) gets @pytest.mark.perf. addopts excludes it from the 12-leg matrix; the Unit Perf Tests job runs it once, in one process, with uv run pytest tests/unit -m perf. Every other unit test runs under a 120s per-test --timeout in CI, and only the ubuntu 3.12 leg measures coverage.
    • An unconditional @pytest.mark.skip must name its ticket in the reason (reason="waits on FND-1234"); the hook in tests/conftest.py fails the test otherwise (FND-4286). Fix or delete a broken test instead of skipping it. skipif is not checked.
    • For how a consumer app's tests should be laid out, read docs/agents/canonical-apps.md and then the app itself — not an arbitrary atlan-*-app, which may be mid-migration or carry deprecated patterns.
    • When a fixture stands in for a generated artifact (app/generated/**, atlan.yaml, a served API envelope), build it from a real one and say in a comment which repo it was read from. A fixture with the shape inverted still passes — for a reason unrelated to its claim — and it flatters the code under test, which is APP-TESTS-001's self-certifying PR arriving through the fixture rather than the assertion. FND-1667 shipped one: a credential template written as {"id": ...} with no config, where the toolkit emits config and no id. Nothing caught it until someone ran the selector against a real tree.
    • When the generated artifact can be rendered here, render it instead of copying it. Each fixture listed in tests/regen_fixtures.py (today tests/unit/handler/fixtures/generated_bigquery_credentials/, rendered from fixtures/bigquery_contract/app.pkl) is toolkit output; tests/unit/test_rendered_fixtures.py renders each one again with the pinned pkl and fails when a copy is stale. To add one, write its contract and add an entry to FIXTURES. After changing a contract or contract-toolkit/src, run uv run poe regen-test-fixtures and review the diff. The Linux unit legs install pkl and set SDK_TESTS_REQUIRE_PKL, so the check cannot pass there by skipping. tests/unit/validation/resources/artifact_schemas.json is held to its toolkit example the same way, by test_fixture_is_the_generated_example.
    • addopts has --strict-markers: a mark not listed in [tool.pytest.ini_options].markers (or registered by a plugin) fails collection. Register a new mark there before using it.
    • No reruns and no flaky marker: CI runs each test once. Fix a flaky test in place.
    • The conformance package's own tests (packages/conformance/tests/) share helpers through tests/_helpers.py: ids / active_ids (all findings vs unsuppressed only — the runner gate's view), write_py, scan_files(scan_all, tmp_path, files), uv_lock, extract_node and sdk_root(). Import them (from tests._helpers import active_ids) instead of copying a helper from the nearest test file. Seven drift guards (test_contract_ledger_drift, test_dependency_audience, test_deprecations_manifest, test_public_errors_drift, test_removed_imports, test_sdk_type_aliases_drift, test_toolkit_baseline_drift) get the monorepo root from sdk_root(), which fails under CI and skips only locally: a miss in CI means the layout changed, which is when the guard is needed. Other drift tests (for example test_sdk_contract_fields_drift) do not use it yet; a new path-based drift guard should.
    • The CI script tests (.github/scripts/tests/) run under .github/scripts/pytest.ini, not the root config. Its pythonpath makes every script and every shared helper there (_workflows.py, _frozen_clock.py, _gha_expr.py, …) importable by name, so never add a sys.path.insert for either directory (test_pytest_ini.py fails one). Read workflow YAML through _workflows.py instead of a per-file _load / _job / _step. See docs/standards/ci.md ("Running the script tests").
    • For consumer apps built on this SDK, the conformance suite's T-series (packages/conformance/conformance/docs/rules/tests.md) enforces the agreed per-connector testing-tier architecture (unit + integration required, e2e recommended, UI optional except for top connectors) plus test-quality checks — assertion-free tests, uncollectable test files, disabled coverage gates, and more. Run it with /remediate or uv run atlan-application-sdk-conformance detect --series T.

    Shared Harness Doubles

    The four harness seams each have one shared double under tests/unit/testing/: _atlas_fakes.py (pyatlan), _cluster_fakes.py (Kubernetes), _temporal_fakes.py (Temporal) and _ae_fakes.py (Automation Engine). Use them; do not write a per-file _FakeAE or a private _node / _succeeded / _result builder.

    • FakeAE implements every public AEClient method with the client's parameters, records each call's bound arguments (ae.calls_to(m), ae.args(m, *names), ae.methods), and serves scripted poll_native_status readings in order. test_ae_fakes.py fails when a client method is added or its signature changes, so update the fake in the same PR.
    • Build DAGRunResult / DAGNodeResult with node(), run_result(), succeeded(), failed(), stalled() and numbered() from the same module.
    • A test that needs failure behaviour the constructor cannot script (for example, a submit that reports a run id and then raises) uses a thin FakeAE subclass that calls super().

    Shared State Under xdist

    An xdist worker runs many tests in one process, and threads from earlier tests (offloads, log flushes) are still running. Keep every test's changes local:

    • Never patch a stdlib function through an SDK module path. patch("application_sdk.X.time.monotonic") patches the one global time module, so the event loop and every thread see the fake. Use tests.unit.private_stdlib.private_stdlib(X, "time") and patch the copy it yields. tests/unit/test_no_global_stdlib_patches.py fails the global forms.
    • Never importlib.reload an SDK module. A reload makes new class and enum objects that earlier importers do not see. Put import-time env parsing in a _load_*() function and test that.
    • Use monkeypatch.setenv / delenv / chdir / syspath_prepend, not os.environ / os.chdir / sys.path directly.
    • tests/unit/conftest.py already resets, around every unit test: the App and Task registries, the infrastructure context, the sizing sink, psycopg2's encodings map, and os.environ. It also loads the hypothesis unit profile (deadline=None); do not call settings.load_profile in a test module.

    Timeouts a Passing Test Must Beat

    A healthy test must never have to finish inside a timeout that exists to prove the failure path. On a loaded 4-vCPU runner — Windows especially, where Event.wait(0.001) rounds to ~15.6 ms and thread-pool spin-up is slow — the success path misses a short bar and reads as a TIMEOUT, an unverifiable source, or a hang.

    • Any timeout a passing test must beat is ≥5s; ≥30s when it covers subprocess or pool spin-up. This includes pytest.mark.timeout, the bound you give asyncio.wait_for, and every budget or deadline handed to the code under test.
    • Short timeouts are only for tests whose subject is the timeout, and only on the step that hangs: test_source_probes.py's _cut_off("tcp") keeps DNS and TLS generous while cutting TCP short.
    • pytest.mark.timeout counts fixture setup too, and on Windows its thread method calls os._exit, killing the whole xdist worker — a "worker crashed" red with no FAILED line. Use it only as a hang guard (timeout(30)).
    • Prove "did not wait" or "did not block the loop" structurally, not with a wall-clock upper bound: record the budget at the seam that would wait (test_restart_marker.py's idle fixture), or assert that a blocked call has not finished when the loop observes it (test_sql_client_cancellation.py). A lower bound (elapsed >= budget) is safe; an upper bound measures runner load.

    Never Assert on Elapsed Wall-Clock Time

    assert elapsed < 1.0, assert lag < 0.1, assert ticks >= n measure the CI runner, not the code: a loaded 4-vCPU runner misses the bar with nothing wrong and one matrix leg goes red at random (FND-4233). Assert the property instead:

    • The event loop stayed free — route the blocking cost through tests/unit/loop_probe.py::LoopProbe.block() and call assert_loop_stayed_free.
    • A budget or remaining time — inject the clock (clock=, a module-local _monotonic seam) or freeze the one the code reads; assert the exact value.
    • It returned promptly / did not wait for a blocked call — have the blocked call set a flag only when it returns and assert the flag is unset once the caller has returned; or bound the wait with asyncio.wait_for / Event.wait at 5–30s, so the bound decides how long a regression takes to fail, never whether a healthy run passes.
    • A complexity guard (linear, not quadratic) — count the steps; failing that, size the input so the regression takes minutes and bound it at 30s. A ratio of two millisecond timings swings past any bar under load, even fastest-of-five.

    tests/unit/test_no_wall_clock_asserts.py fails on any new ordered assertion over a clock delta or a value named elapsed/lag/ticks/gap(s)/took.

    Asserting a Preflight Gate Verdict

    The gate emits one Preflight gate outcome row per invocation and picks the log level from the verdict (FND-901): error for a block or an unverifiable source, warning when it proceeded with a failed advisory check, info otherwise. Read the row through the shared capture rather than patching preflight_gate.logger by hand — a reader that watches info alone returns an empty list on exactly the runs it was written to pin, and keeps passing:

    from application_sdk.testing import capture_preflight_outcomes  # in conftest.py


async def test_block_names_the_failing_check(capture_preflight_outcomes):
    ...
    assert capture_preflight_outcomes.level == "error"
    assert capture_preflight_outcomes.matrix[0]["name"] == "credentialScopes"

    The capture patches nothing: it adds a loguru sink for the test and records the outcome rows the gate's real logger delivers to it. A passing assertion therefore proves the row reached a sink at that level with those bound fields, which a stand-in logger cannot — the adapter runs exactly as in production, so each row also carries the context it stamps (app_name, source, …).

    Suites that patch the logger with a MagicMock themselves can use outcome_rows / outcome_level / single_outcome over the mock instead; prefer the fixture. Both paths assert exactly one row, because returning the first match hides a double emission.

    Boundary: the capture covers rows the gate activity emits. The workflow wrapper's skipped / no_verdict rows go through Temporal's workflow.logger (app/base.py), which the capture does not read — pin those paths against workflow.logger directly.

    Asserting Other Log Lines

    Assert a log line from the record a real sink received, not from a patched module logger. A MagicMock logger proves a method of that name was called; it cannot prove the record reached a sink at that level, rendered, with the bound fields that survive export. Two of these tests hid real export defects while they read a mock, and now pin them as strict xfails.

    • loguru_capture (tests/unit/conftest.py) yields every raw loguru record emitted during the test; filter on record["extra"]["logger_name"] and record["level"].name.
    • gate_records (tests/unit/execution/conftest.py) is that filter for the preflight gate's non-outcome lines: gate_records("WARNING").
    • To check what is exported, run the record's extra through _build_extra_dict — the allowlist the OTLP and NDJSON sinks apply. A key it drops is counted on log.extra_key.dropped; to assert on that counter, see the drop_state fixture in tests/unit/observability/test_log_extra_allowlist.py.

    Registry Isolation

    AppRegistry / TaskRegistry resets have one definition: clean_app_registry and clean_task_registry in application_sdk.testing.fixtures. The unit and integration conftests apply them to every test through an autouse fixture, so a test needs no reset of its own. Request them by name only where ordering matters — a fixture that registers an app must run after the reset.

    Do not add a setup_method / teardown_method, try/finally, or fixture whose job is AppRegistry.reset() or TaskRegistry.reset(). pytest runs the conftest autouse fixtures before a class's setup_method and tears them down after teardown_method, so each test already starts and ends with both registries empty.

    clear_infrastructure() is different: only tests/unit/conftest.py clears the infrastructure context around every test. In tests/unit, do not add that cleanup either. In tests/integration, a test or fixture that calls set_infrastructure must still clear it in its own finalizer, or the next test on the worker inherits the context.

    Call a reset inside a test only when the reset is the behaviour under test (an app that is no longer registered, a cleared context).

    What SDK Review Checks for Tests

    The reviewer enforces these test rules (G4 guardrail):

    • New public API (class/method/module exported in __init__.py) -> MUST have tests
    • Bug fix PR -> MUST have a regression test
    • Security fix PR -> MUST have a regression test
    • Performance fix PR -> MUST have a behavior test
    • Code quality / docs / v2 cleanup -> existing tests passing is sufficient

    Test Patterns the Reviewer Flags

    • @pytest.mark.asyncio or @pytest.mark.anyio (redundant with asyncio_mode="auto" — remove it; only a non-default argument such as loop_scope="session" needs the mark)
    • assert result or assert result is not None (too vague — assert specific values)
    • Missing clean_app_registry fixture when defining App subclasses in tests
    • Real external calls in unit tests (use MockStateStore, MockSecretStore, MockPubSub)
    • Missing MockHeartbeatController for heartbeat-enabled @task methods
    • Tests checking implementation details instead of behavior
